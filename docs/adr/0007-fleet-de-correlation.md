# ADR 0007 — Treat the tool's own fleet signature as a first-class threat

**Status:** Accepted · **Date:** 2026 · **Serves:** Principles I, IV, VII ·
**Threat vectors:** V2b (fleet/cohort correlation), V2 (rarity, "too clean")

## Context

Most anti-detect tooling optimizes one profile at a time: make *this* fingerprint
coherent (V1) and individually common (V2). That is necessary but not sufficient.
The vector that has historically *killed* stealth tools once they became popular
enough to be worth profiling is different in kind: a detector collects many
examples produced by the same tool and learns to recognize the **generator**, not
the profile. Even when every individual fingerprint passes every single-profile
test — including CreepJS-class suites and every external tester — the *population*
a tool emits can share higher-order structure: the same dataset sampled the same
way, the same rule validator, the same noise algorithm, the same bundled font
byte-sets, the same handful of over-represented "safe" personas.

This is invisible to the entire class of single-profile checks a tool normally
grades itself on. So a tool can be green everywhere and still be fingerprintable
*as a class*. We name this vector **V2b** in the
[threat model](../01-threat-model.md) and decide here how seriously the
architecture must take it.

A closely related failure is being **too clean**: real populations carry a
distribution of small, coherent imperfections (a slightly-behind patch version, an
odd extra font, a non-standard resolution). A generator that always emits the
*maximally* tidy persona sits in the thin tail of the "how coherent are real
devices" distribution — a rarity signal no single coherence rule flags, because
nothing is contradictory, only implausibly perfect.

## Options

1. **Ignore it (per-profile only).** Optimize each profile for V1/V2; treat
   cross-user correlation as out of scope or a "later" concern. Simplest; matches
   what most tools do.
2. **Assert it, don't measure it.** Claim de-correlation in docs (independent
   seeds, no magic value) but provide no population-level test. Cheap, but
   unfalsifiable — and Principle IV forbids protective claims we can't back with a
   probe.
3. **Make it a first-class, measured design commitment.** Build the generator so
   fleet spread matches the real world by construction, sample realistic
   imperfection, forbid constant generator artifacts, and *measure* residual
   cohort signal with an adversarial classifier that is a tracked regression
   metric.

## Decision

**Adopt option 3.** Fleet de-correlation and realistic-imperfection sampling are
first-class design commitments, not optimizations to add later, and V2b is a
measured, non-degrading gate — not an aspiration.

Concretely, this commits the project to:

- **Anti-clustering sampling.** The generator reproduces the real population's
  spread *including its tails*, rather than collapsing onto a few modal personas.
  Two users asking for "most common US desktop" must not deterministically get the
  same persona; over-representation is itself a fleet signal.
  ([tdd/02](../tdd/02-fingerprint-engine.md) §9.)
- **Per-profile noise *shape*, not just value.** The statistical shape of
  canvas/audio/WebGL perturbation (amplitude profile, spectral signature,
  quantization) is drawn per-profile, never a fleet-wide constant.
- **Coherence as a distribution.** The generator samples coherent imperfections at
  real-world rates so profiles are realistically — not maximally — tidy, while the
  rule validator still forbids any true incoherence.
  ([tdd/02](../tdd/02-fingerprint-engine.md) §6a.)
- **No constant generator artifact.** No shared magic value, and no single
  canonical bundled-font byte-set presented across unrelated devices.
- **An adversarial red-team classifier as the gate.** The verification lab trains a
  classifier to separate "generated by Proteus" from real fingerprints across a
  batch of profiles; its success is a regression metric, and whatever it keys on
  becomes the next fix and then a permanent probe.
  ([tdd/06](../tdd/06-verification-lab.md) §5a.)

## Rationale

- **It is the vector that actually kills popular stealth tools.** Precisely because
  it only bites *after* a tool is widespread, it is easy to defer and fatal to
  defer. Building the defenses in from the start is far cheaper than retrofitting
  anti-clustering into a generator whose distribution has already shipped.
- **The mitigation is architectural, so it must be decided early.** Independent
  noise *shape*, tail-preserving sampling, and imperfection modeling constrain how
  the sampler, the dataset, and the noise design are built. They cannot be bolted
  on without touching all three.
- **It is testable, which makes the claim honest (Principle IV/VII).** An
  adversarial classifier converts "we de-correlate the fleet" from an
  unfalsifiable slogan into a number that can regress and block a release. This is
  the same move the whole project makes elsewhere: measure, don't assert.
- **It is a genuine differentiator.** Distribution-driven single-profile
  generation has prior art (e.g., Apify's browserforge/fingerprint-suite). Treating
  the *fleet* signature as a measured adversarial target is far less common and is
  something an open, self-attacking project can do credibly where a closed tool
  cannot.

## Consequences

- The fingerprint dataset must carry not just marginals but realistic *joint*
  structure and imperfection distributions, raising the bar on the cold-start
  dataset ([tdd/02](../tdd/02-fingerprint-engine.md) §7a).
- The verification lab gains a population-level, adversarial component
  ([tdd/06](../tdd/06-verification-lab.md) §5a) that must be fed a legal, fresh
  reference corpus *without* collecting raw user fingerprints — public reference
  data plus opt-in differential-privacy aggregates only.
- Release gating (tdd/05) includes the cohort-classifier metric; a fleet that
  becomes separable blocks a release the same way a V1–V5 regression does.
- Some convenience shortcuts are now forbidden by policy (quantizing all DPRs,
  one canonical timezone per region, a single Proteus font bundle) because each is
  a latent cohort tell; reviewers check for them.
- There is an accepted tension to tune empirically: injecting realistic
  imperfection (§6a) trades a little against per-profile blend-in (§6). The
  balance is resolved against the red-team classifier, not by taste
  ([tdd/02](../tdd/02-fingerprint-engine.md) §14).

## Notes

This ADR is the load-bearing commitment behind the V2b vector and the
coherence-as-distribution and red-team-loop designs. It extends Principle I:
"consistency > hiding uniqueness > erasing traces" is now read at the *fleet*
level too — a profile must blend into the real crowd, and the crowd of Proteus
profiles must blend into the real world.
