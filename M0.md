# M0 — Foundations & the Ruler: Implementation and Evidence Status

This file distinguishes two facts that must not be conflated:

1. The **local ruler and repository-side hard-M0 contracts are runnable**.
2. The non-UI code includes a GitHub-hosted reference path for pinned
   three-platform builders, six-run A/B evidence, OIDC/Sigstore attestations,
   complete bundle manifests, dependency/toolchain locks, artifact SBOMs, live
   reports, aggregation, and a fail-closed hard gate.
3. The roadmap's **M0 production path and exit are not complete**. The current
   repository has no runner backend with enough macOS build storage, and the
   independently controlled external-ephemeral lifecycle is not implemented.
   Repository code or fixtures alone cannot make the milestone green.

The hard milestone definition remains
[`docs/06-roadmap.md`](docs/06-roadmap.md). Local checks do not weaken it.

## Commands

```bash
# Install the exact test-only schema-validation dependencies.
npm ci

# Expected to pass: local ruler/tooling scaffold checks.
npm run m0:local

# Succeeds only inside (or with artifacts from) the authenticated hard gate.
npm run m0:milestone
```

Both commands print the same local and hard-exit audit. `m0:local` exits on
local regressions only; `m0:milestone` also requires the active real patch, a
dedicated three-platform build workflow, independently authenticated
provenance, complete-bundle reproducibility evidence, and builder-attested live
reports.

## What still blocks the roadmap M0 exit

- Six successful builder runs—A/B for Windows x64, macOS universal, and Linux
  x64—have not yet been produced for the current source commit.
- Full Chromium builds need roughly Chromium-scale fresh storage. The current
  GitHub-hosted-only builder path cannot satisfy that requirement on its macOS
  runner class.
- The external-ephemeral verifier schema is not an execution backend. A safe
  route still needs a separately trusted controller, pinned public key,
  single-use runner provisioning, post-destruction receipt signing, and an
  independent finalizer. A build runner cannot honestly self-assert that it has
  already been destroyed.
- Any future GitHub larger-runner label must carry an OS prefix understood by
  the API verifier (`linux-`/`ubuntu-`, `windows-`, or `macos-`/`darwin-`);
  Linux and Windows builders additionally require an X64 host. This naming and
  architecture contract is checked before compilation.
- Until aggregation verifies matching A/B bundle trees, raw Sigstore bundles,
  GitHub run/job/check/artifact identities, and the artifact-driven reports,
  `npm run m0:milestone` remains red.

The implemented entrypoint layer binds two distinct paths and physical
identities, exact entrypoint/provenance/report bytes, the pinned Chromium source
and active-series digest, declared invocation/platform fields, the controlled
probe bytes, and a V1–V5 runtime baseline whose summary is independently
recomputed. The baseline need not be green; that is M1/M2 work.

The legacy entrypoint layer intentionally reports
`entrypoint-release-signed-scaffold/v1`. The implemented hard roadmap gate
requires `full-bundle-builder-attested/v2`: complete bundle manifests, six
independent workflow identities, GitHub OIDC/Sigstore attestations, effective
args/toolchains/dependencies, artifact SBOMs, and live reports. This prevents
synthetic fixtures or a single release signer from turning the milestone green.

Chromium compilation also needs a real checkout, `depot_tools`, platform
toolchains, substantial disk/compute, codesigning/notarization, and build-farm
credentials. None of those are fabricated by the local gate.

## Parallel progress beyond M0

The non-UI **M1A config-generation core** is implemented under
[`fingerprint/`](fingerprint/): deterministic persona sampling, strict semantic
validation, a versioned shared seed dataset, a deterministic canonical JSON
contract for the strict Profile Config domain, Ed25519 signing, fail-closed
ingest verification, and Rust↔Node conformance vectors.

That work reduces M1 risk but does not satisfy the native-engine exit criteria.
M1 still requires real Chromium config ingest, native surfaces, cross-context
propagation, and external/runtime verification.
